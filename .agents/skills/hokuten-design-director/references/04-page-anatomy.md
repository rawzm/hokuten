### Menu overlay — superseded 2026-08-10 (D17, Design Revisit 2, replaces the "Stone anatomy" rebuild below)

**What's retired.** The 2026-08-08 rebuild immediately below (the Stone anatomy: ~1/3 art panel, ~2/3 dark index panel) fixed the P0 overlap defect correctly, but shipped generic dialog sizing/overflow classes at the overlay boundary (inset margin, `overflow-y-auto`, a tall single-column index) that Razim's second-round screenshot flagged: a visible sliver of page at the edges, and a normal-case scrollbar most users shouldn't ever see. **Current spec — a true full-bleed screen:**
- **Surface.** `fixed inset-0`, `100dvh` × `100vw`, zero outer margin/padding/border/radius. No visible sliver of the underlying page at any edge, at any device-pixel zoom in Chromium, Safari, or Firefox. Dialog semantics/primitives (Radix or equivalent) stay — only the sizing/overflow classes at the boundary change.

The image renders **full source color, no grayscale filter** — a supplied real hotel photo or approved 「北天」 glyph-mosaic artwork (never stock; ref 01 → Motif system). Essential detail stays clear of the top-left 112×112px close-control zone (§4.2 asset spec).
- **Theme lockup** sits top-right of the navigation panel (a new placement — the header carries its own lockup independently; this is the menu's own instance), with a real-text fallback. - **Index.** The same nine numbered destinations as "Menu index" below, now arranged in **two columns on standard desktop: 01–05 in the first, 06–09 in the second** — this, not a scrollbar, is what makes nine large rows fit. Numbers stay in a separate mono gutter column, clearing the label's left edge by a visible margin (carried forward from the Stone digest); labels stay serif display. Hover = accent underline draw-in + the number brightens to full accent (unchanged).
- **Utilities row** (phone · email · `PRIVATE ACCESS →` ghost link to a100 Arms) pins to the bottom row and **never overlaps the index** — a hard non-negotiable this time, since overlap was the original P0.
- **Overflow contract.** At normal acceptance viewports, the overlay's `scrollHeight === clientHeight` — no scrollbar. Short-height, landscape-mobile, and 200%-zoom layouts get an accessible document/dialog overflow **fallback** instead — a system scrollbar in that exceptional mode is correct behavior (never clip a destination to avoid one). This is the one caller `scroll-well`/native overflow may still legitimately serve (ref 03 §Spacing & layout).

## Per-section spec

**Density, D6 (2026-08-08) — applies to every section below, not repeated per section.** Every desktop section targets fit-to-viewport (`section-fit` utility, ≈100svh minus nav/ticker — `--screen-fit` in `globals.css`). Section padding compresses sitewide (`section-pad`, already compressed 2026-08-08; use `section-pad-tight` where a section carries dense content or sits adjacent to a same-surface neighbour). Two adjacent sections on the same surface share **one** gutter, not two (`section-join` on the second of the pair) — no dead bands between sections. Mobile is exempt everywhere: natural document flow, no fit-to-viewport constraint.

**Superseded 2026-08-10 (D10/D14, Design Revisit 2).** The line that used to close this paragraph — "where a section's content genuinely exceeds the viewport (documented case: `#calculator` step 3), it scrolls inside the section via native overflow (`scroll-well` utility)" — is retired **specifically for the calculator**: D14 rebuilds it as five steps precisely so nothing inside `#calculator` ever needs a nested well again (see `#calculator` below; `scroll-well` itself survives in `globals.css` for the menu overlay's documented exceptional-viewport fallback only, ref 03). The general D10 replacement for "content genuinely exceeds the viewport" is now: **the panel's `min-height` grows and the document scrolls through it before the next snap boundary** (native scroll snap tier only — mobile was always natural flow) — never a section-internal scrollbar as the default expectation. Ref 05's no-scroll-jacking rule is unchanged throughout. The footer's own D6/D18 compaction is at "Footer," below.

## Loader — new 2026-08-10 (D16, Design Revisit 2)

**This narrowly supersedes the earlier reference-digest acceptance line "no preloader ever."** That line came from the Horizonte reference's own accessibility complaint about a percentage preloader; it is not repealed as a general caution — a loader with a fake percent, a long theatrical wait, or one that fires on every navigation is still exactly the anti-pattern that line warned about. What changed is narrow and explicit: Razim requested a short, branded, conditional loader, and this is its spec.

**When it shows.** The first visit in a browser session, and a real reload/hard refresh. **When it does not:** soft in-page navigation, anchor movement, `bfcache` back/forward restoration, ~~or every section snap (D10's paging is not a navigation event as far as the loader is concerned)~~ — **the snap clause is moot since D22 removed scroll snap (corrected 2026-08-17); the rest of the matrix stands unchanged.**

**Composition.** One centered theme-matched lockup (gold Theme G; the Theme B branch is parked with the theme, 2026-08-17 — the same D1 asset family as the header/Trust/footer, ref 01), a thin progress track beneath it, a quiet theme surface, no percent number, no Apple-logo/OS-chrome copying, no tagline competing with the mark. The real-text brand name stays available to assistive tech, same discipline as every other lockup placement.

**Behavior.** A tiny before-hydration state flag prevents a flash of the underlying page. Progress reflects real readiness milestones where available (fonts ready, first hero image decoded) and may ease through an indeterminate middle, but never fakes an exact network percentage. Target duration: minimum ~550–650ms so it reads intentional, normal completion under 1.4s, **hard cap 2s**, exit transition ~300ms — the loader may never push the route's LCP past its own gate. It must release body scroll on every path: success, timeout, and error alike. Session/reload detection uses `sessionStorage` plus Navigation Timing defensively; if storage is denied, the loader fails open (shows the site, does not block).

**Reduced motion / forced colors.** No sliding/chasing animation — a static filled segment and a short opacity-only exit. Forced-colors mode keeps a visible outline/track.

**Component:** a small client island (`BrandLoader` or equivalent) plus the minimal pre-hydration initializer needed to prevent the content flash — see [03-visual-system.md](03-visual-system.md) → Components and [05-motion.md](05-motion.md) for the motion-token detail.
